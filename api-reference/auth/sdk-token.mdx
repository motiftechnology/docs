## Deprecated

<Warning>
**This endpoint is deprecated.** Use **[POST /api/v1/apps/:appId/tokens](/api-reference/apps/issue-token)** instead.
</Warning>

## Why the change?

- **Security:** The new endpoint supports **API key** auth (`X-Api-Key` + `X-Api-Secret`) so your backend never sends app credentials in the request body. Your **frontend** receives only a **token** from your backend—never keys.
- **Consistency:** Token issuance is now under the Apps API (`/apps/:appId/tokens`). You use **App ID**, **public key**, and **secret key** on your **backend** only.

## New flow

1. **Your backend** calls `POST /api/v1/apps/:appId/tokens` with either:
   - **JWT:** `Authorization: Bearer <access_token>`
   - **API key:** `X-Api-Key` (pk_…) + `X-Api-Secret` (sk_…)
2. **Request body:** `{ "external_user_id": "user_123", "name": "Jane", "email": "jane@example.com" }`
3. **Response:** `{ "token", "expires_in", "user_id" }`
4. **Your backend** returns the `token` to your frontend.
5. **Frontend** uses the token with the SDK or WebSocket—never keys.
